# 补全提示词 3：补齐 split/merge 的页面刷新恢复能力

你是资深 React 工程师。

任务：在不引入新业务功能、尽量不改后端 API 的前提下，为 split 和 merge 任务补齐页面刷新后的恢复能力。

修改范围：
- `frontend/src/hooks/useSegments.js`
- `frontend/src/hooks/useGeneration.js`
- `frontend/src/store/videoStore.js`
- `frontend/src/store/generationStore.js`

要求：
1. 使用 `sessionStorage` 或等价的最小持久化方式，保存：
   - `currentVideoId`
   - 当前激活的 `splitTaskId`
   - 当前激活的 `mergeTaskId`
2. 页面初始化时，如果存在 `currentVideoId`：
   - 先调用已有 `GET /videos/:id` 恢复 `currentVideo`；
   - 再按已有逻辑恢复 `analysis` 和 `segments`。
3. 如果存在 `splitTaskId`：
   - 调用现有 `GET /tasks/:taskId` 恢复 `splitProgress`；
   - 如果任务已完成，再自动刷新 `segments`。
4. 如果存在 `mergeTaskId`：
   - 调用现有 `GET /merge/:taskId/progress` 恢复 `mergeProgress`；
   - 如果任务已完成，保留下载入口。
5. 不要改现有后端接口，不要引入新的 UI 模块。
6. 若恢复失败，要清理无效 `sessionStorage`，避免脏状态。
7. 保持单页工作台现有布局不变。

预期结果：
- 刷新页面后，用户还能回到当前处理中的视频，并继续看到分割/拼接任务进度。
