# 补全提示词 2：补齐分析超时后的结果恢复，不改现有分析接口

你是资深 React + Node.js 工程师。

任务：在不改动现有 `/api/analysis/analyze` 接口语义的前提下，补齐“整片分析请求超时但后端最终成功落库”的前端恢复逻辑。

修改范围：
- `frontend/src/hooks/useAnalysis.js`
- `frontend/src/services/api.js`
- 如有必要，可补一个小工具函数到 `frontend/src/utils/`

要求：
1. 保持 `POST /analysis/analyze` 仍然直接发起分析，不新增后端任务接口。
2. 如果 `analyzeVideo()` 因超时或网络异常失败，但当前 `currentVideo.id` 存在：
   - 不要立刻把页面永久标记为失败；
   - 进入一个“结果确认中”或继续轮询状态；
   - 使用已有 `GET /analysis/:videoId` 周期性查询分析结果，直到拿到分析数据或达到最大重试次数。
3. 如果后端最终落库成功，要自动 `setAnalysis`，恢复页面展示。
4. 如果超过最大重试次数仍没有结果，再显示明确失败态。
5. 不能改变已有按钮文案和主交互。
6. 给这个场景补一条测试提示注释，说明需要覆盖“POST 超时但 GET 最终成功”的场景。

预期结果：
- 后端分析慢时，前端不会因为 30 秒超时就把流程彻底判死。
