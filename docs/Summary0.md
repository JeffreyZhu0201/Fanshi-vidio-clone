# Summary

更新时间：2026-04-22

这份文档用简单的话总结：项目现在能做什么、哪里已经打通、哪里还需要继续盯。

## 1. 项目现在是什么

这是一个“视频重生成工作台”。

它现在的核心流程是：

1. 上传原视频
2. Gemini 做整片理解
3. 按整片理解结果切出大片段和小镜头
4. 在页面里编辑角色、场景、大片段、小镜头提示词
5. 用 Gemini 生角色图和场景图，用 Seedance 生小镜头视频
6. 把镜头拼回大片段，再把大片段拼成成片并导出

它已经不是单一步骤的小工具，而是一个完整的“分析 + 资源库 + 片段工位 + 导出”的应用。

- Seedance 已经真实生成成功过 2 个小镜头
- 这个成功的小镜头下载到本地后，时长已经被裁回原镜头时长
- 后端重启后，已在远端运行中的 Seedance 任务可以继续恢复轮询并回写完成结果
- 成片拼接和下载链路保持可用

这次顺手修掉的关键问题：

- `AnalysisDisplay` 之前会无限刷新，控制台报 `Maximum update depth exceeded`
- 资源卡按钮会被右侧区域挡住，显示得到但点不中
- 小镜头部分典型帧会 404
- Seedance 参考视频缺少像素总数过滤
- Seedance 太短的镜头生成后没有裁回原时长
- 生成单镜头时会无差别自动保存，导致别的已完成镜头被误判旧
- 失效时间和数据库任务时间精度不一致，刷新后会把同秒新任务误隐藏
- `nodemon` 或后端重启会中断本地轮询，导致远端已完成但数据库任务还停留在 `processing`
- 服务启动时没有恢复在途任务，长任务需要手工补救
- Seedance 在小镜头生成时会因为输入真人帧图或敏感参考图，直接返回 `InputImageSensitiveContentDetected`，导致镜头任务秒失败

## 4. 现在已经有的核心能力

### 4.1 整片理解

整片理解会返回：

- 剧情摘要
- 角色列表
- 场景列表
- 大剧情片段列表
- 每个大片段下面的小镜头列表

时间规则已经固定：

- 大片段时间是整片绝对秒数
- 小镜头时间也是整片绝对秒数
- 前端需要时再换成片段局部时间

### 4.2 小镜头资产

每个小镜头现在都会尽量有：

- 自己的源视频
- 自己的典型帧图片
- 自己的最终提示词

这意味着后面的镜头生成，不再只靠整段原片。

### 4.3 长任务恢复

现在长任务多了一层启动恢复：

- 如果大片段生成任务已经创建过远端 Seedance 任务，会在服务启动后继续追这个远端任务
- 如果小镜头生成任务已经创建过远端 Seedance 任务，也会在服务启动后继续追这个远端任务
- 如果某个大片段已经处在“等待镜头全部完成后自动拼回”的状态，服务启动后也会继续尝试拼回

这层恢复的目标很明确：

- 不让后端重启把真实生成结果卡死在 `processing`
- 不让已经付费或已经排队的远端任务白跑

### 4.4 资源库

角色资源区现在支持：

- 原始典型帧
- 当前最终提示词
- 三视图预览位
- 编辑详情
- 提示词优化

场景资源区现在支持：

- 原始典型帧
- 当前最终提示词
- 背景图预览位
- 背景资产状态
- 编辑详情
- 提示词优化

### 4.5 片段工作台

每个大片段现在能看到：

- 大片段时间
- 大片段最终提示词
- 小镜头卡列
- 每个小镜头的源预览
- 每个小镜头的典型帧
- 每个小镜头的最终提示词
- 新镜头预览位
- 新大片段预览位

编辑弹窗里现在还能做：

- 优化大片段提示词
- 优化小镜头提示词
- 新增小镜头
- 保存镜头
- 单独生成某个小镜头
- 一键生成全部小镜头

当前已经确认：

- 单镜头真实完成过
- 前端进度条会动
- 背景资产会先准备
- 远端任务在后端重启后可以自动恢复并最终完成
- 当 Seedance 拒绝输入图片时，后端会自动先去掉原片抽帧图重试；还不行再去掉全部参考图重试
- 真实复测里，一个之前会立刻失败的人像小镜头，现在已经拿到新的远端任务 ID 并进入 `running`

但还需要继续完整复测：

- 批量全部镜头成功

- 再拿拼回后的大片段参与最终整片 merge

## 6. 当前最重要的实现约定

### 6.1 小镜头真值来源

小镜头真值只来自整片理解里的：

- `time_anchors[*].shots`

### 6.2 提示词展开规则

真正发给生成模型前，会做两类替换：

- `@角色` -> 角色资源真实提示词
- `#场景` -> 场景资源真实提示词

### 6.3 镜头保存规则

现在规则已经比之前更稳：

- 如果改了镜头结构，比如开始时间、结束时间、典型帧时间、新增镜头，生成前会先保存并重建镜头资产
- 如果只是继续用当前编辑器里的提示词生成，不会再无条件重建所有镜头资产

这样做的目的很直接：

- 不让一个镜头的生成把别的已完成镜头误清空
- 不让刷新页面后同秒新任务消失
