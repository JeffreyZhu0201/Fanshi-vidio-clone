# Summary

更新时间：2026-04-25

这份文档用简单的话总结：项目现在能做什么、哪里已经打通、哪里还需要继续盯。

## 1. 项目现在是什么

这是一个“视频重生成工作台”。

它现在的核心流程是：

1. 上传原视频
2. Gemini 做整片理解
3. 按整片理解结果切出大片段和小镜头
4. 在页面里编辑角色、场景、大片段、小镜头提示词
5. 用 Gemini 生角色图和场景图，用 Seedance 生小镜头视频
6. 把镜头拼回大片段，再把大片段拼成成片并导出

它已经不是单一步骤的小工具，而是一个完整的“分析 + 资源库 + 片段工位 + 导出”的应用。

- 如果 Seedance 在输出审核阶段提示 `output video may contain sensitive information`，通常是提示词里有医疗、药品、病痛类描述；现在发送前会自动改成更中性的供应商安全表达
- Seedance 现在已经彻底禁用“本地复制原视频作为 mock 结果”的回退；远端失败时会直接报错，不再拿原片充数

- 多段视频拼接如果失败，现在会直接报错，不再复制第一个输入文件充当“拼接成功”
- 单镜头大片段拼回现在会标记为 `single-input-copy`，表示“复制真实远端小镜头结果作为大片段结果”，不再混用 `mock-copy`

- 片段卡和镜头编辑里现在会显示“本次实际发送给 Seedance 的参考图 / 参考视频 / 参考音频”清单，能直接看到这次到底喂了典型帧、三视图、场景图还是背景视频
- 角色编辑弹窗现在可以维护“状态时间线”，保存后会自动刷新所有相关镜头的状态引用
- 小镜头编辑弹窗现在会展示：对白全文、逐句字幕、说话方式、参考音频、SRT 下载与复制入口
- 小镜头生成时现在会优先把“原镜头音频 + 角色状态参考帧 + 角色三视图 + 场景图”一起送给 Seedance
- 小镜头最终参考图现在固定按配额进入 Seedance：`典型帧 1 张 + 人物三视图 3 张 + 场景图 3 张 + 角色状态参考帧最多 2 张`，不再因为整体截断把场景图或人物三视图挤掉

## 4. 现在已经有的核心能力

### 4.1 整片理解

整片理解会返回：

- 剧情摘要
- 角色列表
- 每个角色的状态时间线
- 场景列表
- 大剧情片段列表
- 每个大片段下面的小镜头列表
- 每个小镜头的对白 / 字幕 / 说话方式
- 每个小镜头绑定的角色状态引用

时间规则已经固定：

- 大片段时间是整片绝对秒数
- 小镜头时间也是整片绝对秒数
- 角色状态时间线也是整片绝对秒数
- 小镜头字幕时间是相对当前小镜头本地时间
- 前端需要时再换成片段局部时间

现在整片理解的真实调用顺序是：

1. 只把整段原视频直接发给 `Gemini-2.5-pro`
2. 要求它一次性返回整片剧情、角色、场景资源、大片段和每个大片段下的全部小镜头
3. 如果这一次调用失败，就直接把真实错误返回前端

现在 `生成片段` 的真实顺序是：

1. 直接读取整片分析已经返回的 `time_anchors`
2. 本地 FFmpeg 切出大片段文件
3. 直接把 `time_anchors[*].shots` 写入 `segment.analysis.shots`
4. 本地为每个小镜头切源视频、抽典型帧、补音频 / 字幕资产
5. 写入 `segments`，前端刷新后直接显示片段卡

现在不会再发生这个旧行为：

- 点击 `生成片段` 后，再对每个大片段自动发一次 Gemini 片段分析才建卡

现在不会再发生这些旧行为：

- 不再自动切到关键帧顺序采样回退
- 不再自动切到 `gemini-2.5-flash`
- 不再自动掉回 mock 整片分析

现在这条链路已经补了一个启动兜底：

- 如果旧数据库里还没有 `analyses.analysis_options`
- 后端启动时会自动补齐这个字段
- 这样前端再点“整片分析”不会因为漏跑迁移直接 500

这次针对“前端显示远端错误 fetch failed”的实际修复点是：

- 后端已经把 Gemini、Gemini 生图、Seedance 统一改成 Node.js 外部请求层
- 统一请求层默认先走 `undici`，会读取系统代理配置，当前环境可通过 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY` 出网
- 如果 `undici` 在 TLS 握手阶段报 `ECONNRESET / before secure TLS connection was established`，统一请求层会自动回退到 Node 原生 `http/https` 直连，避免整片分析直接 `fetch failed`
- 整片分析主路径现在固定为单次 `Gemini-2.5-pro` 请求，不再做模型、鉴权变体、关键帧和 mock 回退
- 整片分析 prompt 已经加强成“更细镜头拆分 + 更精确时间点”，要求尽量按真实镜头切点返回 `shots`
- 整片分析后端超时现在默认放宽到 `600000ms`，可通过 `GEMINI_WHOLE_VIDEO_TIMEOUT_MS` 调整

前端开发访问现在有一个新约束：

- 本地开发服务默认跑在 `http://localhost:5173`
- 外部访问走 `https://frp-fox.com:42734`
- 这是为了避免 frp 回源到本地自签 HTTPS 时直接 `502 EOF`
- `frontend/vite.config.js` 现在已经显式放行 `VITE_ALLOWED_HOSTS`

### 4.2 小镜头资产

每个小镜头现在都会尽量有：

- 自己的源视频
- 自己的典型帧图片
- 自己的最终提示词

这意味着后面的镜头生成，不再只靠整段原片。

### 4.3 长任务恢复

现在长任务多了一层启动恢复：

- 如果大片段生成任务已经创建过远端 Seedance 任务，会在服务启动后继续追这个远端任务
- 如果小镜头生成任务已经创建过远端 Seedance 任务，也会在服务启动后继续追这个远端任务
- 如果某个大片段已经处在“等待镜头全部完成后自动拼回”的状态，服务启动后也会继续尝试拼回

这层恢复的目标很明确：

- 不让后端重启把真实生成结果卡死在 `processing`
- 不让已经付费或已经排队的远端任务白跑

### 4.4 片段复用与防重复生成

现在“生成新片段”多了一层复用判断：

- 如果当前大片段已经有最新拼回预览，而且当前镜头提示词和比例都没变，再点“生成新片段”会直接复用已有结果
- 如果当前只有镜头级成功结果，还没有新的大片段预览，系统会把这些旧成功镜头结果直接复用到本轮批处理中，再立即拼回
- 单独点“生成当前镜头”时，如果这个镜头已经有同提示词、同比例的成功结果，也会直接返回旧任务，不再重复调模型

这层逻辑的目标很直接：

- 不让已经有预览的视频继续反复调用 Seedance
- 不让“旧镜头成功、新批次 started_at 变了”这种情况把拼回卡死

角色资源区现在支持：

- 原始典型帧

- 三视图预览位

场景资源区现在支持：

- 会自动尝试候选模型，而不是只死打一个模型名
- 对 TLS EOF、连接超时这类网络抖动增加了重试
- 前端失败文案不再只显示 `fetch failed`，会尽量落成“渠道不可用”或“连接不稳定”
- 这次已经重新实测通过：
- 单张角色三视图图像可真实生成
- 完整三视图资源包可连续生成并落库

现在外部 AI 接口调用方式已经统一：

- Gemini 文本理解：Node.js `undici`
- Gemini 图片生成：Node.js `undici`
- Seedance 视频生成、轮询、结果下载：Node.js `undici`
- 不再依赖命令行 `curl` 执行业务接口请求

Seedance 现在的资源发送规则：

- 优先发送 `PUBLIC_ASSET_BASE_URL + /uploads/...` 形式的公网 URL
- 角色三视图、场景图、典型帧都会作为 `reference_image`

- 创建远端任务默认最多等 `120s`，生成结果下载默认最多等 `300s`
- reference video 总时长默认最多 `15.2s`
- 单次生成时长现在按 `15s` 上限保护；超过时不会再盲发请求，而是直接提示先重新细分镜头
- 长镜头会优先保留小镜头源视频，背景资产视频只在不超时长预算时发送
- Seedance 最终提示词会自动做安全改写，例如把“身体不适、痛苦、胸口、药盒”弱化成“疲惫、神情紧张、上衣前侧、小白盒”
- 当前 `frp-fox.com:42734` 是自签证书，浏览器或远端供应商如果严格校验证书，可能仍需要换成可信证书公网域名
- 如果本地资源公网 URL 是自签证书或不可达，系统会自动跳过对应的 `reference_video`，避免坏链接把整条远端任务拖死
- 2026-04-23 这次直接用当前 Key 做了最小 4 秒 Seedance 创建探测，供应商返回 `403 overdue balance`；这说明当前账号存在欠费，新视频任务会被直接拦截，先补齐账务后再测生成

## 5. 现在还不能说完全稳定的部分

### 5.1 Gemini 生图

真实情况不是“完全不通”，也不是“完全稳定”。

现在的真实状态是：

- 接口、鉴权、落库、前端展示都已经接通
- 但上游经常返回 `429` 或并发不足

所以角色三视图和场景图目前应归类为：

- “链路可用”
- “受外部额度和并发影响”

### 5.2 Seedance 批量拼回

当前已经确认：

- 单镜头真实完成过
- 前端进度条会动
- 背景资产会先准备
- 远端任务在后端重启后可以自动恢复并最终完成
- 当 Seedance 拒绝输入图片时，后端会自动先去掉原片抽帧图重试；还不行再去掉全部参考图重试
- 真实复测里，一个之前会立刻失败的人像小镜头，现在已经拿到新的远端任务 ID 并进入 `running`
- 真实复测里，一个已经完成全部小镜头的大片段，在再次点击“生成新片段”后不会再新增任务；直接返回已有大片段预览
- 真实复测里，一个只有旧小镜头结果、但还没拼回成功的大片段，再次点击“生成新片段”后会复用旧镜头结果并在本轮成功拼回

但还需要继续完整复测：

- 批量全部镜头成功
- 自动拼回大片段成功
- 再拿拼回后的大片段参与最终整片 merge

## 6. 当前最重要的实现约定

### 6.1 小镜头真值来源

小镜头真值只来自整片理解里的：

- `time_anchors[*].shots`

### 6.2 提示词展开规则

真正发给生成模型前，会做两类替换：

- `@角色` -> 角色资源真实提示词
- `#场景` -> 场景资源真实提示词
- 说话镜头还会补上对白全文、字幕节奏和说话方式
- 还会补上当前镜头角色状态的 `continuityPrompt`
- 并且统一追加“不要字幕、不要文字、不要水印、不要 UI 浮层”的生成约束

当前发给 Seedance 的镜头级提示词顺序已经固定为：

1. 整片剧情目标
2. 大片段最终提示词
3. 小镜头最终提示词
4. 展开的 `@角色` 资源提示词
5. 当前镜头角色状态 `continuityPrompt`
6. 展开的 `#场景` 资源提示词
7. 对白文本 / 字幕节奏 / 说话方式
8. 不要字幕 / 不要文字 / 不要水印 / 不要 UI

### 6.3 镜头保存规则

现在规则已经比之前更稳：

- 如果改了镜头结构，比如开始时间、结束时间、典型帧时间、新增镜头，生成前会先保存并重建镜头资产
- 如果只是继续用当前编辑器里的提示词生成，不会再无条件重建所有镜头资产

这样做的目的很直接：

- 不让一个镜头的生成把别的已完成镜头误清空
- 不让刷新页面后同秒新任务消失
