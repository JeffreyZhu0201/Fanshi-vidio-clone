# Summary

更新时间：2026-04-25

这份文档只写当前仓库里已经实现的真实功能、真实流程和当前限制，不写理想状态。

## 1. 项目现在是什么

这是一个“视频重生成工作台”。

当前主流程是：

1. 上传原视频
2. 选择全局风格、比例和分析选项
3. Gemini 做整片理解
4. 按整片结果切出大片段和小镜头
5. 生成角色三视图和场景参考图
6. 优化大片段和小镜头提示词
7. 用 Seedance 生成小镜头
8. 把小镜头拼回大片段，再把大片段拼成成片

## 2. 这次改动后，已经明确接通的部分

### 2.1 全局风格模式

现在新增了全局风格模式：

- `写实`
- `漫剧`

默认是 `写实`。  
`漫剧` 当前固定按“国漫影视化”处理。

风格模式现在已经统一作用到：

- 整片理解提示词
- 片段理解提示词
- 角色三视图生成提示词
- 场景三视图生成提示词
- 提示词优化
- Seedance 最终视频生成提示词

风格状态现在保存在 `analysis_options` 里，不新建表，不改现有 URL。

### 2.2 整片理解和片段理解提示词

现在这两类分析提示词都改成了“两段式”：

- 固定结构段：字段要求、JSON 结构、时间规则、输出规则，只读
- 风格段：自然语言风格约束，可编辑

这意味着：

- 用户现在只能编辑风格段
- 不能直接改 JSON 骨架
- 切换 `写实` / `漫剧` 时，各自风格段独立保存，不互相覆盖

### 2.3 风格模板共享

前后端现在共用一套风格模板真值，放在：

- `shared/styleTemplates.js`
- `shared/promptBlueprints.js`

这里现在统一管理：

- `videoAnalysisStylePrompt`
- `segmentAnalysisStylePrompt`
- `characterThreeViewStylePrompt`
- `sceneThreeViewStylePrompt`
- `videoGenerationStylePrompt`
- `promptOptimizationStylePrompt`

其中只有两项允许用户编辑：

- `videoAnalysisStylePrompt`
- `segmentAnalysisStylePrompt`

资源图风格块和视频生成风格块目前仍跟随预设，不开放自由编辑。

### 2.4 Seedance 语音超长适配

现在说话镜头在发送给 Seedance 前，多了一层“镜头时长适配”：

- 先把真正有声的部分压进镜头时长内，并额外预留一点结尾收口余量
- 压缩后同步缩放 `subtitleLines` 时间轴
- 然后再把整条参考音频补到 Seedance 实际生成时长，后半段只保留静音缓冲
- 如果需要的压缩倍率超过 `1.5x`，直接阻止生成并报明确错误

这样做的目的是：

- 镜头时长不变
- 尽量保留完整台词
- 避免最终裁片时把台词尾部切掉
- 下载远端结果后，如果对白镜头生成出来的是静音视频，会直接判失败，不再当成功结果返回

### 2.5 当前已确认可用的主链路

已经重新确认通过的部分：

- 前端页面可以正常打开
- 原视频上传、去重、hash 文件名落盘可用
- 整片理解当前固定主用一次 `Gemini-2.5-pro`
- 整片理解后端长超时已放宽，且会对 `429`、`socket hang up`、`ECONNRESET` 这类瞬时网络中断做同模型重试
- 整片理解结果会落库到 `analyses`
- 大片段切分和小镜头切分可用
- 小镜头源视频、典型帧、参考音频、SRT 可落盘
- 角色三视图和场景参考图现在会跟随当前风格模板生成
- 资源提示词优化、大片段提示词优化、小镜头提示词优化现在都会带入当前风格模式
- Seedance 单镜头生成会吃当前风格模式和全局风格硬约束
- 小镜头最终会优先使用角色三视图、场景图，再把典型帧只作为站位和机位参考
- Seedance 不再允许用原视频复制成 mock 结果充数
- 后端重启后，可以恢复在途 Seedance 任务并继续轮询
- 成片拼接和下载链路继续可用

## 3. 现在的真实流程

### 3.1 上传与全局设置

上传后，当前视频会进入工作台上下文。  
页面上现在有两个全局控制项：

- 视频比例
- 风格模式

分析选项仍然保留：

- `提取字幕`
- `音频解析`

当前默认仍是双开。

### 3.2 整片理解

整片理解现在的真实行为是：

1. 只调用一次 `Gemini-2.5-pro`
2. 对较大视频会先在本地转一个低分辨率、低帧率的整片分析代理视频，再把代理视频发给 Gemini
3. 如果 `extractSubtitles` 和 `parseAudio` 都关闭，整片分析代理视频会直接去掉音轨，进一步减少上传体积
4. 提示词由“固定结构段 + 可编辑风格段”拼装
5. 要求返回整片剧情、角色、大片段和小镜头
6. `analysis_options` 会决定这次整片理解是否同时返回每个小镜头的 `speech`
7. 后端本地派生 `backgrounds`
8. 后端补角色 `stateTimeline`
9. 后端把角色状态引用补回 `timeAnchors[*].shots[*].characterStateRefs`

当前整片分析结果里最重要的真值有：

- `plot`
- `characters`
- `backgrounds`
- `time_anchors`
- `time_anchors[*].shots`
- `characters[*].stateTimeline`
- `time_anchors[*].shots[*].characterStateRefs`
- `analysis_options`

说明：

- 如果 `extractSubtitles` 或 `parseAudio` 开启，小镜头 `speech` 现在会在整片分析阶段一次性返回并落库
- 如果这两个选项都关闭，整片分析不会返回 `speech`
- 如果整片分析遇到 `socket hang up`，后端会自动重试；重试耗尽后会明确提示“远端连接中途断开或网络不稳定”
- 整片分析仍然只调一次 Gemini；新增的本地代理视频只是在发请求前把上传体积压小

### 3.3 生成片段

`生成片段` 现在不会再在 split 循环里重新调用 Gemini 做每个大片段分析。

它现在只做：

1. 读取整片分析里的 `time_anchors`
2. 切出大片段文件
3. 把 `shots` 透传到 `segment.analysis.shots`
4. 切小镜头源视频
5. 抽小镜头典型帧
6. 切小镜头音频
7. 把整片分析里已经返回的 `speech` 落成 SRT 和本地音频资产
8. 返回片段卡

这样前端在切分完成后就能直接看到片段卡，不需要再等第二轮 Gemini。

### 3.4 资源图与提示词优化

资源图和提示词优化现在都吃当前风格模式。

当前规则：

- `写实`：保持写实影视感
- `漫剧`：保持国漫影视化

影响范围：

- 角色三视图
- 场景参考图
- 角色资源提示词优化
- 场景资源提示词优化
- 大片段提示词优化
- 小镜头提示词优化

### 3.5 小镜头生成

小镜头生成当前优先使用：

1. 角色三视图
2. 场景参考图
3. 小镜头典型帧
4. 小镜头源视频
5. 小镜头参考音频
6. 背景资产视频

补充规则：

- 小镜头典型帧现在只负责提供人物左中右站位、前后景层次、机位朝向、视线和动作瞬间
- 不再要求生成结果和关键帧高度贴脸；它更像同镜头的重拍版本
- 人物外观优先由角色三视图替换原片人物
- 场景外观优先由场景参考图替换原片空间与布景

最终发送给 Seedance 的提示词，会把：

- 整片剧情目标
- 大片段提示词
- 小镜头提示词
- 全局视频风格硬约束
- 展开的角色 / 场景资源提示词
- 角色状态连续性文字约束
- 对白与说话方式约束

一起拼进去。

如果当前镜头有对白：

- 会先检查参考音频是否超长
- 超长则先把有声部分压进镜头时长内
- 然后再把整条参考音频补到 provider 实际生成时长，避免最终裁回镜头时切掉尾句
- 压缩倍率超过 `1.5x` 就直接阻止生成
- 下载远端结果后还会检查最终视频是否真的带音轨；如果没有音轨，任务直接失败

### 3.6 拼回和成片导出

当前规则保持不变：

- 小镜头全部成功后，按顺序拼回大片段
- 大片段有新结果时，整片 merge 优先用新结果
- 没有新结果时，再回退原大片段

## 4. 当前提示词顺序

这里写当前真实顺序，不写理想顺序。

### 4.1 整片理解提示词

当前由两部分组成：

1. 固定结构段
2. 风格段

固定结构段里写死：

- JSON 字段结构
- 时间规则
- `shot` 必填字段
- `shot.prompt` 约束
- 不要字幕 / 不要文字 / 不要 UI / 不要水印

风格段当前取自：

- `analysis_options.styleTemplates[styleMode].videoAnalysisStylePrompt`

### 4.2 片段理解提示词

当前也由两部分组成：

1. 固定结构段
2. 风格段

风格段当前取自：

- `analysis_options.styleTemplates[styleMode].segmentAnalysisStylePrompt`

这一步只刷新大片段理解和大片段 prompt，不会重写 `shots`。

### 4.3 提示词优化

现在所有优化模式都会带入当前风格模式：

- `generation`
- `shot_generation`
- `character_resource`
- `scene_resource`

### 4.4 Seedance 最终提示词顺序

当前真实顺序是：

1. 整片剧情目标
2. 大片段最终提示词
3. 小镜头最终提示词
4. 全局风格硬约束
5. 资源展开后的生成真值
6. 镜头还原和连续性硬约束
7. 角色三视图替换原片人物的硬约束 / 角色状态连续性文字约束
8. 场景参考图替换原片空间的硬约束
9. 对白文本、字幕节奏、说话方式
10. 对白时长约束
11. 必须输出带完整音轨的视频文件，参考音频存在时音频与口型尽量对齐
12. 不要字幕 / 不要文字 / 不要 Logo / 不要 UI / 不要水印

## 5. 接口与字段变化

没有新增 URL，没有改现有端点路径。

当前新增的是可选字段：

### 5.1 `analysis_options`

现在包含：

- `extractSubtitles`
- `parseAudio`
- `styleMode`
- `styleTemplates`

其中 `styleTemplates` 当前只保存可编辑项：

- `realistic.videoAnalysisStylePrompt`
- `realistic.segmentAnalysisStylePrompt`
- `comic_drama.videoAnalysisStylePrompt`
- `comic_drama.segmentAnalysisStylePrompt`

### 5.2 可选 `style_mode`

以下接口现在支持可选 `style_mode`：

- `POST /api/segments/:id/analyze`
- `POST /api/analysis/optimize-prompt`
- `POST /api/generation/generate`
- `POST /api/generation/shots/generate`
- `POST /api/generation/shots/generate-batch`

说明：

- 没传时，回退到 `analysis_options.styleMode`
- 传了时，只影响这次调用，不会自动重跑旧结果

## 6. 当前仍需继续盯的部分

### 6.1 Gemini 生图

现在不是代码没接上，而是上游仍可能：

- `429`
- 网络抖动

所以当前状态是：

- 链路可用
- 稳定性受上游影响

### 6.2 Seedance 账务与长任务

当前代码已经做了：

- 创建超时放宽
- 在途任务恢复
- 参考图 / 参考视频 / 参考音频筛选
- 语音超长压缩

但如果供应商账号欠费或外部排队过长，任务仍会失败或等待很久。

## 7. 一句话总结

这次改动后，主流程的“风格控制”和“对白时长适配”已经进入真实链路：

- 全局 `写实 / 漫剧` 已经贯穿分析、资源图、优化和视频生成
- 整片理解与片段理解都改成“固定结构只读 + 风格段可编辑”
- Seedance 说话镜头现在会先把有声部分压进镜头时长，再把整条参考音频补到 provider 生成时长，尽量保证裁回镜头后台词仍完整
- Seedance 说话镜头下载完成后会校验最终文件是否带音轨，静音结果会直接判失败
- 小镜头生成现在改成“角色三视图 / 场景图主导，关键帧只负责站位和机位参考”，避免生成结果和关键帧过于相似
- 小镜头不再额外发送人物状态典型帧，人物状态连续性改为由整片理解里的 `stateTimeline + continuityPrompt` 统一控制
