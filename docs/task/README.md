## 🚀 使用流程

### 第一步: 阅读基线与架构文档
- 阅读 [0.项目理解与开发约束.md](./0.项目理解与开发约束.md)
- 阅读 [Overall_Arch.md](../Overall_Arch.md)
- 理解项目整体设计

### 第二步: 按阶段执行
1. 打开对应阶段的任务文档
2. 复制提示词到 GPT/Claude
3. 让 AI 生成代码
4. 按照检查清单验收

### 第三步: 提交代码
```bash
git checkout -b feature/阶段名
# 编写代码
git add .
git commit -m "feat: 阶段名 - 功能描述"
git push origin feature/阶段名
# 创建 PR，审查后合并到 develop
```

### 第四步: 合并到主分支
```bash
git checkout develop
git pull origin develop
git checkout main
git pull origin main
git merge develop
git push origin main
```

## 📝 提示词使用指南

### 如何使用提示词

1. **复制完整提示词** - 从文档中复制整个提示词块
2. **粘贴到 GPT/Claude** - 在 AI 工具中粘贴
3. **等待代码生成** - AI 会生成规范的代码
4. **审查代码** - 检查代码质量和完整性
5. **集成到项目** - 将代码放入对应目录

### 提示词特点

- ✅ 包含完整的需求说明
- ✅ 明确的代码规范
- ✅ 详细的文件结构
- ✅ 具体的实现要求
- ✅ 最佳实践指导

## 📞 常见问题

### Q: 提示词可以修改吗?
A: 可以。根据实际需求调整提示词，但要保持核心要求不变。

### Q: 可以跳过某个阶段吗?
A: 不建议。每个阶段都是后续阶段的基础，跳过会导致后续问题。

### Q: 如何处理提示词生成的代码有问题?
A: 
1. 检查提示词是否完整
2. 调整提示词的细节
3. 让 AI 重新生成
4. 手动修复代码

### Q: 多人协作如何分工?
A: 
- 前端工程师负责阶段 4
- 后端工程师负责阶段 2、3
- DevOps 工程师负责阶段 6
- QA 工程师负责阶段 5
