## 数据库设计提示词

```
你是一个资深数据库架构师。

任务：为 Fanshi-vidio-clone 项目设计 MySQL 数据库 schema。

要求：
1. 创建数据库 fanshi_video_db

2. 设计以下 5 张核心表：

   a) projects 表 - 项目信息
      - id (PK, AUTO_INCREMENT)
      - user_id (FK, 用户ID)
      - name (VARCHAR 255, NOT NULL)
      - description (TEXT)
      - status (ENUM: 'draft', 'processing', 'completed', 'failed')
      - created_at (TIMESTAMP)
      - updated_at (TIMESTAMP)
      - 索引: user_id, status

   b) videos 表 - 视频文件
      - id (PK, AUTO_INCREMENT)
      - project_id (FK, NOT NULL)
      - filename (VARCHAR 255, NOT NULL)
      - file_path (VARCHAR 500, NOT NULL)
      - duration (INT, 视频时长秒数)
      - file_size (BIGINT, 文件大小字节)
      - status (ENUM: 'uploaded', 'analyzing', 'analyzed', 'failed')
      - created_at (TIMESTAMP)
      - updated_at (TIMESTAMP)
      - 索引: project_id, status

   c) analyses 表 - 视频分析结果
      - id (PK, AUTO_INCREMENT)
      - video_id (FK, NOT NULL, UNIQUE)
      - plot (LONGTEXT, 剧情内容)
      - characters (JSON, 角色形象数组)
      - backgrounds (JSON, 背景描述数组)
      - time_anchors (JSON, 时间锚点数组)
      - gemini_response (LONGTEXT, 原始 Gemini 响应)
      - created_at (TIMESTAMP)
      - updated_at (TIMESTAMP)
      - 索引: video_id

   d) segments 表 - 视频片段
      - id (PK, AUTO_INCREMENT)
      - video_id (FK, NOT NULL)
      - segment_index (INT, 片段序号)
      - start_time (DECIMAL 10,2, 开始时间秒)
      - end_time (DECIMAL 10,2, 结束时间秒)
      - file_path (VARCHAR 500, 片段文件路径)
      - analysis (JSON, 片段分析结果)
      - created_at (TIMESTAMP)
      - updated_at (TIMESTAMP)
      - 索引: video_id, segment_index

   e) generation_tasks 表 - 生成任务
      - id (PK, AUTO_INCREMENT)
      - segment_id (FK, NOT NULL)
      - prompt (LONGTEXT, 生成提示词)
      - optimized_prompt (LONGTEXT, 优化后提示词)
      - status (ENUM: 'pending', 'processing', 'completed', 'failed')
      - result_url (VARCHAR 500, 生成结果 URL)
      - progress (INT, 进度百分比 0-100)
      - error_message (TEXT, 错误信息)
      - created_at (TIMESTAMP)
      - updated_at (TIMESTAMP)
      - 索引: segment_id, status

3. 设置外键关系：
   - videos.project_id → projects.id (ON DELETE CASCADE)
   - analyses.video_id → videos.id (ON DELETE CASCADE)
   - segments.video_id → videos.id (ON DELETE CASCADE)
   - generation_tasks.segment_id → segments.id (ON DELETE CASCADE)

4. 编写 SQL 初始化脚本 (backend/config/init.sql)

5. 编写 Sequelize 模型文件：
   - models/Project.js
   - models/Video.js
   - models/Analysis.js
   - models/Segment.js
   - models/GenerationTask.js

6. 配置模型关系 (hasMany, belongsTo)

7. 编写数据库连接测试脚本

代码规范：
- 使用 Sequelize ORM
- 模型定义清晰
- 关系配置完善
- 时间戳自动管理
- 软删除考虑 (可选)
```

## Sequelize 模型提示词

```
你是一个资深 Node.js ORM 专家。

任务：为 Fanshi-vidio-clone 项目编写 Sequelize 模型。

要求：
1. 在 backend/models/ 目录创建模型文件

2. 每个模型包含：
   - 字段定义 (类型、约束、默认值)
   - 时间戳配置
   - 索引配置
   - 验证规则
   - 关联关系

3. 在 backend/models/index.js 中：
   - 导入所有模型
   - 配置关系 (hasMany, belongsTo, hasOne)
   - 导出模型对象

4. 编写 backend/config/database.js：
   - 创建 Sequelize 实例
   - 配置连接池
   - 同步数据库 (sequelize.sync())

5. 编写 backend/utils/dbInit.js：
   - 初始化数据库连接
   - 创建表
   - 创建索引

代码规范：
- 使用 DataTypes 定义字段类型
- 关系配置使用 foreignKey
- 验证使用 validate 对象
- 时间戳使用 timestamps: true
```

## 数据库迁移提示词

```
你是一个数据库迁移专家。

任务：为 Fanshi-vidio-clone 项目创建数据库迁移脚本。

要求：
1. 安装 sequelize-cli: npm install --save-dev sequelize-cli

2. 初始化迁移配置: npx sequelize-cli init

3. 创建迁移文件：
   - migrations/001-create-projects.js
   - migrations/002-create-videos.js
   - migrations/003-create-analyses.js
   - migrations/004-create-segments.js
   - migrations/005-create-generation-tasks.js

4. 每个迁移文件包含：
   - up() 方法 (创建表)
   - down() 方法 (回滚)

5. 编写 package.json scripts：
   - "db:migrate" - 执行迁移
   - "db:migrate:undo" - 回滚迁移
   - "db:seed" - 填充测试数据

代码规范：
- 迁移文件命名规范
- 幂等性设计
- 错误处理完善
```
